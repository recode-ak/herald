# Пачка вопросов по очереди — итог трека

Spec — [spec.md](./spec.md), план — [plan.md](./plan.md). Трек: 2026-11-17.

## Сделано

- **Домен:** вопрос — пачка из 1–10 пунктов с общим сроком; одиночный — пачка из одного. Ответ по пункту, `decide` по неотвеченным (ответ агента или рекомендованный), `moveToTerminal`, `answerInTerminal` по пунктам. Новый вид входящих `to-terminal`.
- **Хранилище:** миграция v6 — `questions.items`, `terminal_at`, `message_links.item`; старые строки читаются как пачка из одного.
- **Бот:** пункты приходят по одному («Вопрос 2 из 3»), ответы — агенту одним `answer`. «Жди меня (вся пачка)». «🖥 В терминал» на каждом открытом вопросе (и одиночном): кнопки снимаются, агенту `to-terminal`. Решение агента по неотправленным пунктам — итоговым сообщением, reply на него — указание.
- **HTTP:** `ask` с `questions`, `decide`/`answered` с `answers`, `POST /v1/to-terminal`; `/v1/question` просыпается и при переводе в терминал.
- **Клиенты:** CLI `herald ask --questions`, `--answers`, `herald to-terminal`, код 3 — переведён в терминал. Канал: `ask` с `questions`, `answers`, инструмент `to_terminal`, событие `to-terminal`, инструкции («связанные вопросы — одним ask», «тут» → `to_terminal`). Мост pi доставляет `to-terminal`.
- **Совместимость:** старые запросы и поля ответа прежние; клиент достраивает `items`, если сервер их не прислал (37ba85b).
- **Прод:** выкачен 37ba85b, схема v6.

## Решения без ответа

Нет: стратегические вопросы (модель пачки, очередь, сброс на границе фаз, выкатка) решены Нурболатом. Тактические, принятые сами:

- «🖥 В терминал» есть и у одиночного вопроса (spec так и говорит; обновлены ожидания кнопок в старых тестах).
- HTTP `decide` одиночного вопроса по-прежнему требует `option`/`text`; `answers: []` — явное «все рекомендованные».
- CLI: код выхода 3 для перевода в терминал.
- `herald ask`, ждавший вопрос, отмечает `to-terminal` прочитанным — мост pi не доставит его второй раз.
