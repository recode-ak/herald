# Пачка вопросов по очереди — spec

Утверждено Нурболатом 2026-11-17 (обсуждение в сессии herald·b6b6).

## Обзор

Агент задаёт несколько связанных вопросов подряд, у каждого свой таймаут. Пока человек читает первый, срок остальных идёт, и непонятно, дождётся ли агент. Когда вопросы приходят все сразу, это неуютно.

Новое: **пачка** — один `ask` с несколькими вопросами (пунктами) и одним сроком. Человек получает пункты **по одному**: ответил — следующий приходит новым сообщением. herald копит ответы и отдаёт их агенту **одним событием**. Над пачкой два действия:

1. **«Жди меня»** — агенту нельзя решать ни один пункт.
2. **«🖥 В терминал»** — человек ответит в терминале: неотвеченные пункты уходят из бота, агент задаёт их своим UI (в Claude Code — AskUserQuestion) и закрывает инструментом `answered`. Перевести можно из бота (кнопка) и из терминала (человек пишет агенту «тут», агент вызывает инструмент).

Одиночный вопрос — пачка из одного пункта; для него всё как сейчас, плюс кнопка «🖥 В терминал».

## Функциональные требования

### Домен (`Question`)
1. Вопрос — пачка из 1–10 пунктов `{ text, options, recommended? }`, нумерация с 1. Срок, «Жди меня» (`heldAt`) и перевод в терминал (`terminalAt`) — на всю пачку. У пункта — свой ответ (`resolution`) и поздние ответы.
2. Ответ человека на пункт открытого вопроса записывается (повторный, пока вопрос открыт, — заменяет прежний). Отвечены все пункты — вопрос `answered`.
3. `decide` — решение агента по неотвеченным пунктам: ответ на пункт задаёт агент, иначе берётся рекомендованный; без того и другого — ошибка с номером пункта. Вопрос → `decided`. Запрещён без таймаута, после «Жди меня» и после перевода в терминал.
4. `moveToTerminal(now)` — только для `open`; повтор — без ошибки, время не меняется.
5. `answerInTerminal(answers)` — ответы на неотвеченные пункты; отвечены все — `answered`.
6. Ответ на пункт решённого вопроса — поздний (как сейчас, но по пункту).

### Хранилище
7. Миграция: `questions.items` (JSON пунктов с ответами), `questions.terminal_at`, `message_links.item`. Старые строки читаются как пачка из одного пункта.

### Бот
8. Сообщение пункта пачки: шапка сессии, «Вопрос 2 из 3», текст, варианты, срок пачки. У одиночного вопроса строки «из» нет.
9. Кнопки на сообщении текущего пункта: варианты; «Жди меня» (для пачки — «Жди меня (вся пачка)»), пока вопрос открыт, с таймаутом и не удержан; «🖥 В терминал», пока вопрос открыт и не переведён.
10. Ответ кнопкой или reply на сообщение пункта: с него снимаются кнопки, добавляется «👤 Принят B»; есть неотвеченный и вопрос не переведён — следующий пункт приходит новым сообщением. Последний — во входящие агенту одно `answer` со всеми ответами.
11. «Жди меня» — `heldAt`, на сообщении текущего пункта «⏸ Агент ждёт твоего ответа».
12. «🖥 В терминал» — на сообщении текущего пункта кнопки снимаются, строка «🖥 Переведено в терминал — ответь там; reply здесь тоже примется». Следующие пункты не присылаются. Агенту — входящее `to-terminal`: данные ответы и неотвеченные пункты с вариантами и рекомендованным. Сессия не на связи — предупреждение, как у указаний.
13. Решение агента: на сообщении текущего пункта — «🤖 Принят A по таймауту» и кнопки для переигрывания (как сейчас). Неотправленные пункты — одним итоговым сообщением «🤖 Агент решил по таймауту: 2. … — B; 3. … — A»; reply на него — указание сессии.
14. Ответ в терминале (`answered`) — на сообщении текущего пункта итог «👤 Принято в терминале: …».

### Агент
15. HTTP `ask`: `questions: [{ text, options, recommended? }]` или прежние `text/options/recommended` (один пункт); `timeoutMs` — на пачку. `decide`: прежний `option/text` (одиночный) или `answers: [{ item, option | text }]`. `answered`: то же. Новое `POST /v1/to-terminal { id? }` — перевести вопрос или, без `id`, все открытые вопросы сессии; ответ — переведённые вопросы. Во входящие перевод от агента не кладётся.
16. Провод вопроса: `items` всегда; у одиночного — и прежние поля верхнего уровня (старые клиенты работают).
17. Входящие: `answer` по готовности всей пачки (текст — все ответы по пунктам; `option` — только у одиночного), `late-answer` — по пункту, новое `to-terminal`.
18. Канал Claude Code: `ask` с `questions`; `decide`/`answered` с `answers`; инструмент `to_terminal`; событие `to-terminal` с подсказкой «спроси здесь своим UI, закрой answered». В инструкциях: связанные вопросы — одним `ask`; человек в терминале просит спросить здесь («тут», «в терминал») — вызови `to_terminal`.
19. CLI: `herald ask --questions '<JSON>'` (пачка), `herald to-terminal [id]`; `decide`/`answered` — `--answers '<JSON>'`. Мост pi доставляет `to-terminal` сообщением агенту.

## Вне рамок

- Отмена «Жди меня» и перевода в терминал.
- Пункты, зависящие от ответов на предыдущие.

## Критерии приёмки

1. Тесты домена, хранилища, бота, HTTP, канала, CLI и моста pi покрывают требования 1–19; старый одиночный `ask` и старые строки БД работают.
2. Ручная проверка на проде: пачка из 3 с таймаутом — пункты по одному, «Жди меня (вся пачка)», ответы одним событием; «🖥 В терминал» из бота и `to_terminal` из терминала; решение по таймауту с итоговым сообщением.
3. Документы: `docs/model.md` (вопрос, входящие, бот, HTTP, CLI, канал), `docs/install.md` при необходимости.
