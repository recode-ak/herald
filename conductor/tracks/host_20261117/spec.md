# Окна агентов без активного агента — spec

Второй из двух треков про окна агентов. Первый — [spawn_20261117](../spawn_20261117/) — открывает окно через активного агента (`herald spawn`). Здесь — случай, когда активных агентов нет.

## Обзор

Нурболат далеко, активных агентов на машине нет. Он пишет боту `/new`, бот ведёт диалог «машина → каталог → задача», и на машине открывается окно Claude Code с каналом herald (тот же `AgentLauncher`, что у `herald spawn`): задача уходит первым сообщением, сессия появляется в `/sessions`. Лишнее окно он закрывает командой `/exit` — как `/clear`.

## Решения (согласовано 2026-11-17, вопросы `q_eduvumvqro`)

- Запуск — в любом каталоге внутри `~`; проверку делает `AgentLauncher.resolve`. Окна — в tmux-сессии `agents`, на рабочей машине Нурболата.
- **`/new` — пошаговый диалог** в боте: машина → каталог (кнопки последних или ввод) → задача.
- **`/exit` — мягко:** команда терминала сессии, как `/clear` (reply на сообщение сессии или выбор в `/sessions`); канал набирает `/exit` в окне, агент занят — выйдет после хода. Демон в закрытии не участвует.
- **Служба `systemd --user`:** unit задаёт `PATH` (как в оболочке) и `KillMode=process` — иначе tmux-сервер, запущенный демоном, окажется в cgroup службы, и её перезапуск убьёт окна агентов. tmux-сервер стартует сам при первом окне (`new-session`).
- **Токен демона** — тот же из `~/.config/herald/config.json` (токен = машина/контур).
- **Linger не включается:** служба живёт, пока Нурболат вошёл в систему; в `docs/install.md` — заметка.

## Требования

### Сервер

1. **Машина** (`Host`): человек токена + имя (`host` из сессии вызывающего). Отмечается при каждом опросе демона; **на связи** — опрос не старше 2 мин (как у сессии).
2. **Запуск** (`Launch`): `id`, человек, машина, каталог (как ввёл человек), задача, чат и сообщение человека (для ответа), `createdAt`, `takenAt`, `finishedAt`, итог `{ ok, text }`.
   - Выдаётся демону один раз (`takenAt` при выдаче): лучше потерять запуск при падении демона, чем открыть окно дважды.
   - Итог — один раз; повтор — ошибка.
3. **HTTP API** (тело как у всех — `session` с `host`; машина — `session.host`):
   - `/v1/host/poll` `{ waitMs? }` → `{ launches }` — невыданные запуски машины, пусто — ждёт первых до `waitMs`; отмечает машину;
   - `/v1/host/done` `{ id, ok, text }` → `{ ok: true }` — итог запуска; человеку — reply на его сообщение с задачей: «🪟 Окно открыто: …» или «⚠️ Окно не открылось: …» с хвостом экрана. Чужой запуск — 403.
4. **Диалог `/new`** (состояние — на чат, в базе):
   - машин на связи нет — «Нет машин на связи: запусти `herald host`», диалог не начинается; одна — шаг пропускается; несколько — кнопки машин;
   - каталог: кнопки последних корней сессий этой машины (до 8, свежие первыми) и подсказка «или пришли путь от `~`»;
   - задача: следующий текст чата (можно многострочный) — запуск создан, «⏳ Открываю окно на <машина>…»;
   - `/cancel` — отмена; другая `/команда` диалог отменяет и выполняется как обычно; выбор сессии в `/sessions` диалог отменяет, `/new` сбрасывает выбранного адресата;
   - устаревшая кнопка (другой шаг, нет диалога) — «⚠️ кнопка устарела»; машина ушла со связи к шагу задачи — запуск всё равно создаётся, демон заберёт его при опросе.
5. **`/exit`** — новая команда терминала (`InboxItem.COMMANDS`), адресация как у `/clear`.
6. **Хранение:** машины — по последнему опросу, запуски — по `createdAt`, диалоги — по началу; счётчики в отчёте `purge` (`hosts`, `launches`, `dialogs`).
7. Список команд бота в подсказках («Неизвестная команда…», «Кому?») — с `/new`, `/exit`, `/cancel`.

### Клиент

8. **`herald host [--tmux <сессия>] [--timeout <с>]`** — демон машины: цикл `host/poll` → `AgentLauncher.launch` (каталог относительно `~`, сессия `agents`, задача) → `host/done`. Запуски — по одному. Сбои сети и 5xx пережидаются (как у long poll), SIGTERM/SIGINT — выход 0. Лог — stderr (журнал службы).
9. **Канал:** `/exit` набирается в окне, как `/clear`; статус после него не ставится (окно закрывается). Расширение pi `/exit` не знает — человеку «⚠️ /exit не выполнена: …» (как сейчас для неизвестной команды).

### Документы

10. `docs/model.md`: машина и запуск, `/v1/host/*`, диалог `/new`, `/exit`, `/cancel`, `herald host`, хранение. `docs/install.md`: unit `systemd --user` (`PATH`, `KillMode=process`, `Restart=on-failure`), linger. `docs/deploy.md` — без изменений, если не потребуется.

## Критерии приёмки

- `bun run check` зелёный, новый код покрыт тестами (>80%).
- Живая проверка после выкатки (выкатка — **только с подтверждения Нурболата**): служба `herald-host` на машине, `/new` из Telegram открывает окно в `~/herald-livetest`, задача доходит, сессия видна в `/sessions`; `/exit` её закрывает.

## Вне рамок

- Жёсткое закрытие (`kill-window`) зависшего агента — по запросу.
- Самосброс и `/exit` в pi через расширение — по запросу.
- Linger и запуск без входа в систему.
