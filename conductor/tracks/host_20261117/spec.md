# Окна агентов без активного агента — spec (черновик)

> **Черновик.** Записано 2026-11-17 в сессии u7-school, передаётся новой сессии в `~/dev/tools/herald`. Решённое Нурболатом помечено «решено»; остальное — открытые вопросы. Их нужно согласовать с Нурболатом (`ask`, варианты с рекомендованным) **до** плана.

Второй из двух треков про окна агентов. Первый — [spawn_20261117](../spawn_20261117/) — открывает окно через активного агента (`herald spawn`). Здесь — случай, когда активных агентов нет.

## Обзор

Нурболат далеко, активных агентов на машине нет. Он пишет боту `/new …`: на машине открывается окно Claude Code с каналом herald (тот же `AgentLauncher`, что у `herald spawn`), задача уходит первым сообщением, сессия появляется в `/sessions`. Лишнее окно он закрывает командой `/exit`.

## Решено

- Запуск — в любом каталоге внутри `~` (Нурболат: «Все что находится по пути `~/dev`, можно и `~`»). Отдельный белый список не нужен: эту проверку уже делает `AgentLauncher.resolve`.
- Окна — в отдельной tmux-сессии `agents` (как у `spawn`).
- Агенты запускаются на рабочей машине Нурболата. С продом он работает с неё по ssh.
- Механика запуска (стартовые диалоги, задача после `--`) уже есть в `src/terminal/launcher.ts`, её переиспользуем.

## Набросок (согласовать)

1. **Демон машины `herald host`**: служба `systemd --user`. Ждёт long poll команд, адресованных машине (`host` из `~/.config/herald/config.json`), а не сессии. По команде вызывает `AgentLauncher` и докладывает итог: в Telegram приходит «окно открыто» или ошибка с хвостом экрана.
2. **Сервер:**
   - входящие уровня машины: новый адресат `host`, отдельный от сессии;
   - машина отмечается живой, пока демон её опрашивает;
   - команды бота `/new` и `/exit`;
   - выкатка — по `docs/deploy.md`, **только с подтверждения Нурболата**.
3. **`/new [<машина>] <каталог> <задача>`.** Если живая машина одна, её имя можно не писать.
4. **`/exit`** закрывает окно выбранной сессии (из `/sessions`).
5. Документы: `docs/model.md` (API, команды бота, CLI `herald host`) и `docs/install.md` (unit `systemd --user`, переменные окружения: tmux и `claude` в PATH службы).

## Открытые вопросы

- **Синтаксис `/new`.** Строка с аргументами или пошаговый диалог в боте: машина → каталог (последние или ввод) → задача?
- **`/exit`.**
  - Указание агенту (`herald self /exit`): мягко, агент успевает закончить ход.
  - Демон делает `kill-window`: надёжно, даже если агент завис.
  - Оба: сначала мягко, через срок — жёстко.
- **Окружение службы.** У `systemd --user` нет PATH и tmux-сервера пользователя. Варианты:
  - unit задаёт PATH и `TMUX_TMPDIR`;
  - демон сам запускает tmux-сервер, если его нет.
- **Токен демона.** Отдельный токен контура или тот же из `config.json`.

## Вне рамок

- Самосброс в pi через расширение (`newSession` + `sendUserMessage`) — только по запросу.

- Окна запускать в каталоге внутри `~` (например `~/herald-livetest`), потом удалить.
- Claude Code для проверки запускать без MCP (`--strict-mcp-config`), чтобы не слать уведомления в Telegram. Исключение — проверка самого канала.
