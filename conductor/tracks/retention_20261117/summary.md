# Очистка БД herald — итог трека

Spec — [spec.md](./spec.md), план — [plan.md](./plan.md). Трек: 2026-11-17.

## Сделано

- **Домен:** `Retention` — срок хранения в днях (по умолчанию 14) и граница `cutoff(now)`.
- **Хранилище:** миграция v5 — `message_links.created_at`. `Store.purge(cutoff, { dryRun })` удаляет одной транзакцией по политике из `docs/model.md`, «Хранение». Открытые вопросы и непрочитанные входящие уходят только вместе с сессией; `telegram_offset` не трогается.
- **Команда:** `bun run purge [--days N] [--dry-run]`. Выводит JSON (удалено, останется, размер базы), коды выхода 0/1. Срок — `--days`, иначе `HERALD_RETENTION_DAYS`, иначе 14.
- **Бот:** кнопка на удалённом вопросе отвечает «⚠️ вопрос устарел и удалён».
- **Прод:** herald выкачен (схема v5). В server-ops добавлена служба `herald-retention` (коммит `2d674fb`): cron `30 3 * * *` UTC, статус `state/herald-retention/status.json` попадает в отчёты health-check через `40-statusfiles`. Ошибка даёт `crit` и алерт. Статус старше 26 ч даёт алерт «не обновлялся».
- **Документы:** `docs/model.md` («Хранение», `HERALD_RETENTION_DAYS`), `docs/deploy.md` (строка «Очистка»), `docs/install.md` (cron на других установках). В server-ops — README службы, таблица служб, `docs/health-check.md` §4.

## Финальный гейт

`bun run check`: biome и tsc чистые, 382 теста pass / 0 fail. Новые модули покрыты на 100% строк.

На проде: `purge --dry-run` показал 0 к удалению (данным два дня). Ручной прогон службы в окружении как у cron — код 0, `40-statusfiles` показывает 🟢 herald-retention. Путь ошибки (нет каталога) — код 1, причина в stderr.
