# Сообщение без адресата — spec

Запрос Нурболата 2026-11-18 (указание в сессии herald из Telegram). Уточнён его ответом на вопрос q_kw2k5yvbor: меню — всегда, и при одной сессии (в запросе было «одной — сразу»).

## Обзор

В работе через herald часто хочется спросить сессию «как дела?». Сейчас для этого нужен reply на её сообщение — обычно под рукой последний вопрос, и текст уходит агенту **ответом на вопрос**, что его путает. Выбор адресата через `/sessions` работает, но это два лишних шага. Текст без reply и без адресата сегодня — тупик: подсказка «Кому?».

Новое: **на сообщение без адресата бот спрашивает «Кому?»** кнопками сессий на связи; после выбора это же сообщение уходит выбранной. Подходящей нет — «✖ Отмена». Меню — всегда, даже при одной сессии.

## Функциональные требования

### Telegram
1. Апдейт нажатия кнопки несёт **исходное сообщение** — то, на которое сообщение с кнопкой отвечает reply (`callback_query.message.reply_to_message`: `message_id` и `text`). Нет его (удалено, без текста) — поля нет.

### Бот
2. Текст без reply, вне живого диалога `/new` и без выбранного в `/sessions` адресата:
   - сессий на связи нет — «Сессий на связи нет.», во входящие ничего;
   - иначе — меню «Кому?»: reply на сообщение человека, кнопка на каждую сессию на связи (подпись как в `/sessions`) и «✖ Отмена»; при одной сессии — тоже. Во входящие ничего, пока не выбрано.
3. Кнопка сессии в меню: исходное сообщение уходит ей так же, как ушло бы reply (указание, реакция на исходном сообщении, предупреждение «не на связи»); меню перерисовывается без кнопок — «→ <сессия>»; всплывающий ответ — «Адресат: <проект>».
4. «✖ Отмена»: меню перерисовывается без кнопок — «Отменено.»; во входящие ничего.
5. Текст ждёт выбора не в БД: его несёт само нажатие (требование 1). Нажатие без исходного сообщения — «⚠️ кнопка устарела». Повторное нажатие после доставки — «Уже отправлено», второго входящего нет.
6. Кнопка чужой сессии — отказ, как в `/sessions`.
7. Команды терминала (`/clear`, `/compact`, `/exit`) без адресата: то же меню с именем команды — «Кому <команда>?»; выбор → `command` этой сессии. Сессий нет — «Сессий на связи нет.».
8. Без изменений: reply на вопрос — ответ; reply на сообщение сессии — указание или команда; `/sessions` → кнопка → следующий текст — выбранной сессии (адресат важнее правила 2); текст в живом диалоге `/new` — его шаг; reply на сообщение без связи — «Кому? Ответь reply…».

## Вне рамок

- Изменение смысла reply на вопрос (остаётся ответом).
- Хранение ожидающего текста в БД, срок жизни меню.
- Ответ сессии на «как дела?» без участия агента (это `/status`).

## Критерии приёмки

1. Тесты бота и Telegram покрывают требования 1–8; `bun run check` зелёный.
2. `docs/model.md` — бот и входящие.
3. Ручная проверка на проде (после выкатки): текст без reply — меню, выбор, отмена (при одной и при двух сессиях); `/compact` без адресата — меню.
