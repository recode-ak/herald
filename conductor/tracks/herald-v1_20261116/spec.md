# herald v1 — spec

Утверждено Нурболатом 2026-11-16.

## Обзор

Сервис-посредник между агентами и человеком через отдельного Telegram-бота: один бот на все машины, агенты и сессии. Агент шлёт уведомления, статус и вопросы с вариантами; человек отвечает кнопкой или текстом, смотрит статус и пишет указания. Основной клиент — Claude Code: herald работает в нём как свой channel, и сообщения приходят прямо в сессию. Для pi и любого агента с shell — CLI `herald`. Переносимость: clone репо, `bun run link`, конфиг `~/.config/herald/config.json` (`serverUrl`, `token`, `host`).

## Функциональные требования

1. **Сессии.** Ключ сессии — `host + корень git` (или `--session`). Сессия регистрируется при первом обращении, активность определяется по последнему обращению.
2. **notify.** Сообщение получателю токена с шапкой `[host · проект]`. Ошибка доставки возвращает ошибку.
3. **ask.** Вопрос с кнопками вариантов, пометкой рекомендованного и кнопкой «Жди меня». Свободный ответ — reply на сообщение.
   - CLI: `herald ask "…" -o "A: …" -o "B: …" --recommended A [--timeout 180]` блокируется до ответа или таймаута. Результат машиночитаемый (JSON и код выхода: ответ или таймаут). Без `--timeout` ждёт бесконечно.
   - Channel: инструмент `ask` сразу возвращает id вопроса, ответ приходит событием в сессию.
4. **decide.** Решение по таймауту принимает агент: `decide <id> A --reason "по таймауту"`. Сообщение в Telegram обновляется («принят A по таймауту»), кнопки остаются для переигрывания.
5. **Поздние ответы.** Ответ после таймаута или после `decide` сохраняется и доставляется сессии с пометкой «переигрывание вопроса <id>».
6. **status.** Агент обновляет статус сессии: `herald status "…"` или инструмент `status`. В Telegram при этом ничего не отправляется. Бот по `/status` и в `/sessions` отвечает последним статусом с давностью, без участия агента.
7. **Указания человека.** Reply на любое сообщение сессии или выбор сессии в `/sessions` кладёт текст во входящие этой сессии. Сервис текст не толкует.
   - Доставка в Claude Code — событием канала на ближайшем шаге агента.
   - Доставка в остальные агенты — через `herald inbox` на границах задач.
   - В Telegram видны отметки «в ящике сессии X» и «прочитано агентом».
8. **`/sessions`.** Список активных сессий: host, проект, давность активности, статус. Кнопки выбора адресата.
9. **Channel для Claude Code.** MCP-сервер (stdio) с capability `claude/channel` и инструментами `reply`/`notify`, `ask`, `decide`, `status`. Подтверждение действий из Telegram (`claude/channel/permission`) — включается настройкой.
10. **Получатели и доступ.**
    - `HERALD_TOKENS=человек:токен,…` и `HERALD_PEOPLE=человек:chat_id,…`.
    - Ответы и указания принимаются только от chat_id из списка и только по сессиям своего человека.
    - Неверный токен отклоняется.

## Нефункциональные требования

- Bun + TS strict + Biome; SQLite через `bun:sqlite`.
- Зависимости: `@modelcontextprotocol/sdk` (согласована, только в клиенте-канале). Остальные — по согласованию, цель — ноль.
- Telegram опрашивает только сервер (long polling, без webhook). Клиенты в Telegram не ходят.
- HTTP API с Bearer-токеном. Ожидание ответа и входящих — long poll.
- Протокол Channels — research preview. Канал — тонкий слой над тем же HTTP-клиентом, что и CLI: если протокол изменится, правится только канал.
- TDD, `bun run check`. Telegram и сервер в тестах — фейки.
- Деплой как у chronicle: `/srv/herald`, pm2, nginx `herald.u7-hub.kz`, бэкап через `backup.contract`.

## Критерии приёмки

1. `notify` доставляет сообщение, при ошибке — ненулевой код.
2. CLI `ask` возвращает вариант, выбранный кнопкой, или текст reply. По таймауту — статус «нет ответа».
3. `decide` обновляет сообщение в Telegram. Поздний ответ доставляется сессии.
4. `/status` и `/sessions` отвечают без участия агента.
5. Указание через reply или `/sessions` попадает только в нужную сессию: в Claude Code — событием канала, в pi — через `inbox`. Отметки «в ящике» и «прочитано» видны.
6. В Claude Code (`--dangerously-load-development-channels server:herald`) сообщение из Telegram приходит в сессию, `ask` отвечает событием.
7. Чужой chat_id и неверный токен отклоняются.
8. herald развёрнут на kalki-server по `docs/deploy.md`. Установка на новую машину по `docs/install.md` — не больше 5 команд.
9. Инструкция «Автопилот» переведена на herald: вопросы через `ask`; `status` и `inbox` на границах задач; в Claude Code — канал; `agent-notify` и `agent-notify.env` удалены.

## За рамками

Webhook; несколько ботов; веб-интерфейс; толкование команд сервисом; запуск агентов из Telegram (как в Takopi); расширение для pi (позже, если `inbox` на границах задач окажется медленным); автозапуск pm2.
