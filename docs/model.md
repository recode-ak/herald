# Модель herald

Сущности, состояния и правила домена (`src/domain`). Домен синхронный, без ввода-вывода; время — мс эпохи, передаётся снаружи. Нарушение правила — `DomainError`, ошибка конфига доступа — `AccessConfigError`.

Сценарии (`src/app`) — ниже, в разделах «Бот» и «Ожидание»; окна по `/new` — «Машина и запуск», «Диалог `/new`»; HTTP API, настройки сервера и очистка базы — в разделах «HTTP API», «Сервер» и «Хранение». Клиент и команды CLI — в разделе «CLI», инструменты и события канала Claude Code — в разделе «Канал».

## Доступ (`access.ts`)

Кто пользуется herald. Строится из двух строк окружения сервера:

| Переменная | Формат | Смысл |
|---|---|---|
| `HERALD_TOKENS` | `человек:токен,…` | токен агента (по одному на машину/контур) → человек |
| `HERALD_PEOPLE` | `человек:chat_id,…` | человек → его chat_id в Telegram |

Правила: обе строки не пусты; токен и chat_id уникальны; у каждого человека с токеном есть chat_id; chat_id — целое (у групп отрицательный). Из Telegram принимаются апдейты только от chat_id из `HERALD_PEOPLE`.

## Сессия (`session.ts`)

Где работает агент. Регистрируется при первом обращении, принадлежит человеку токена.

| Поле | Смысл |
|---|---|
| `key` | `host:корень` (корень git без хвостового `/`), `host:корень#окно` у сессии Claude Code и pi или `host:@имя` при явном `--session` (оно главнее окна) |
| `project` | имя корня (`u7-school`), с окном — `u7-school·02dc`, или имя сессии |
| `title` | название от агента (≤ 60 символов, `title`); метка в шапке — `проект · название` |
| `lastSeenAt` | последнее обращение агента; **на связи** (🟢) — обращение не старше 2 мин и окно не закрыто. Пульс — long poll входящих: у канала и расширения pi он идёт непрерывно, пока жива сессия агента (и когда агент думает, и когда простаивает); у CLI без них — только во время вызовов |
| `closedAt` | окно агента закрыто (`bye`); снимается следующим обращением |
| `status` | `{ text, at }` — последний статус от агента, ≤ 500 символов; в Telegram сам не отправляется |

## Вопрос (`question.ts`)

Вопрос агента человеку — **пачка** из 1–10 пунктов (одиночный вопрос — пачка из одного). Пункт: текст, варианты `{ id, text }` (могут отсутствовать — тогда только свободный ответ), рекомендованный — из вариантов, свой ответ и поздние ответы. На всю пачку: таймаут (необязателен) → срок `deadlineAt = askedAt + timeoutMs`, «Жди меня» (`heldAt`), перевод в терминал (`terminalAt`). Человек получает пункты по одному; текущий — первый неотвеченный.

```
            answer (человек)
   open ──────────────────────▶ answered
     │  decide (агент, с причиной)
     └────────────────────────▶ decided
```

- `answer(choice, n)` — ответ на пункт `n`: вариант или свободный текст. Вопрос `open` — ответ записан (повторный заменяет прежний); отвечены все пункты — `answered`. Вопрос не `open` — ответ **поздний**: сохраняется в `lateAnswers` пункта, решение не меняется (агент сам решает, переигрывать ли).
- `decide` — только из `open`, только у вопроса с таймаутом, без удержания и не переведённого в терминал; причина обязательна («по таймауту»). Решает неотвеченные пункты: ответ агента на пункт, иначе рекомендованный, иначе — ошибка с номером пункта. Ответы человека остаются. Вопрос без таймаута решает только человек.
- `answerInTerminal` — человек ответил в терминале агента, отмечает агент (`answered`): ответы на пункты с `resolution.via = terminal`; отвечены все — `answered`; не из `open` — ошибка (поздним не бывает). Во входящие не попадает.
- `hold` — кнопка «Жди меня»: вопрос (вся пачка) остаётся `open`, агенту решать нельзя, человек ответит сам.
- `moveToTerminal` — «🖥 В терминал» (или агент по просьбе человека): только из `open`, повтор — без изменений. Бот больше не присылает пункты, агенту решать нельзя; агент задаёт неотвеченные пункты у себя и закрывает их `answered`. Ответ в боте (reply) по-прежнему принимается.
- Таймаут — целое мс ≥ 0 (`0` — агент решит сразу). Сам срок сервер не отслеживает: решает агент, сервер лишь разрешает или запрещает `decide`.
- `resolution` — `{ by: human | agent, option | text, reason?, via?, at }`.

## Входящие (`inbox.ts`)

Что агент забирает из сессии.

| Вид | Когда | Поля |
|---|---|---|
| `answer` | ответ человека на открытый вопрос | `questionId`, `option` или текст |
| `late-answer` | ответ на уже решённый вопрос | `questionId`, `option` или текст |
| `directive` | указание человека сессии (reply или выбор в `/sessions`) | текст |
| `command` | команда терминала сессии: `/clear`, `/compact` или `/exit` (reply или выбор в `/sessions`); выполняет не агент, а канал или расширение pi | текст — команда |
| `to-terminal` | человек нажал «🖥 В терминал»: агент задаёт неотвеченные пункты у себя | `questionId`; текст — что уже отвечено и что спросить (варианты, ⭐ рекомендованный) |
| `hold` | человек нажал «Жди меня» (один раз на вопрос): `decide` запрещён, агент ждёт ответа без срока | `questionId`; текст — что делать |

- Ожидание вопроса (`/v1/question`, `herald ask`) отмечает прочитанными свои `answer`, `to-terminal` и `hold`: агент, ждавший вопрос, получает их ответом, а не входящими.
- `answer` у пачки — один, когда отвечены все пункты: текст — строка на пункт «1. База? — B: JSON», `option` нет. `late-answer` у пачки — по пункту, тем же видом строки.

- Выдача — непрочитанные по времени создания, затем по id.
- Подтверждение прочтения (`ack`) атомарно: неизвестный id — ошибка, ничего не отмечено. Возвращает впервые прочитанные — на их сообщениях в Telegram реакция меняется на «прочитано» (👀).
- Ящик (`Inbox`) — одна сессия; элемент чужой сессии в него не попадает.

## Машина и запуск (`host.ts`)

Окно агента по `/new` открывает демон машины `herald host` (раздел «CLI»): он опрашивает сервер и запускает Claude Code с каналом.

**Машина** (`Host`) — человек токена + имя (`host` из сессии демона). Отмечается при каждом обращении демона (`lastSeenAt`); **на связи** — обращение не старше 2 мин, как у сессии.

**Запуск** (`Launch`) — окно, которое человек попросил открыть:

| Поле | Смысл |
|---|---|
| `id` | `l_…` |
| `person`, `host` | человек и имя машины |
| `dir` | каталог, как его выбрал или ввёл человек (`~/x`, `dev/x` — от `~`, абсолютный); проверяет и раскрывает демон |
| `prompt` | задача — первым сообщением агенту |
| `chatId`, `messageId` | сообщение человека с задачей: на него — reply с итогом |
| `createdAt`, `takenAt`, `finishedAt` | создан, выдан демону, получен итог |
| `outcome` | `{ ok, text }` — окно открыто (`text` — окно, каталог) или ошибка (с хвостом экрана) |

- Выдаётся демону **один раз** (`take`): потерять запуск при падении демона лучше, чем открыть окно дважды.
- Итог (`finish`) — только у выданного и один раз; текст не пуст.

## Диалог `/new` (`new-window.ts`)

Состояние — на чат (один диалог), в базе: шаг (`host` → `dir` → `prompt`), машины на связи с каталогами, выбранные машина и каталог, `startedAt`.

- Машин на связи нет — диалог не начинается. Одна — её шаг пропускается.
- Каталоги машины — корни её сессий у этого человека, свежие первыми, без повторов, до 8.
- Машина — кнопкой или текстом (только из предложенных); каталог — кнопкой или текстом (любой путь); задача — следующий текст (можно многострочный) — диалог завершён, запуск создан.
- Кнопка не того шага или не того номера — «кнопка устарела». Метка диалога (`token`, из `startedAt`) — в кнопках: кнопка прежнего диалога — устаревшая.
- Забытый диалог (старше 1 ч) не перехватывает сообщения и удаляется.

## Бот (`src/app/human.ts`, `agent.ts`, `new-window.ts`)

Сообщения агента (уведомление, вопрос) — `parse_mode: HTML`: шапка и вопрос жирным, варианты строками, текст агента — из упрощённого Markdown (`src/app/markup.ts`: **жирный**, _курсив_, ~~зачёркнутый~~, `код`, блоки ```, ссылки http(s), заголовки `#`, списки). Telegram не разобрал разметку — то же сообщение уходит обычным текстом. Служебные сообщения бота — без разметки. Шапка — `[host · метка сессии]`.

| Действие человека | Результат |
|---|---|
| кнопка варианта на вопросе | ответ на пункт, сообщение перерисовано; у пачки — следующий пункт новым сообщением, после последнего — одно `answer` со всеми ответами. Вопрос уже решён — `late-answer` пункта |
| «Жди меня» (у пачки — «Жди меня (вся пачка)»; кнопка есть, пока пункт открыт, вопрос не удержан и задан с таймаутом) | `hold` всей пачки: агенту решать нельзя, в сообщении «⏸ Агент ждёт твоего ответа»; агенту — входящее `hold` |
| «🖥 В терминал» (пока пункт открыт и вопрос не переведён) | `moveToTerminal` и `to-terminal` агенту: кнопки сняты, «🖥 Переведено в терминал — ответь там; reply здесь тоже примется», следующие пункты не приходят |
| reply на вопрос | свободный ответ на пункт этого сообщения — так же, как кнопка |
| reply на итог решения агента по неотправленным пунктам | `directive` этой сессии |
| reply на другое сообщение сессии (уведомление, своё указание или ответ) | `directive` этой сессии |
| `/clear`, `/compact`, `/exit` — reply на сообщение сессии (и на вопрос) или после выбора в `/sessions` | `command` этой сессии; без адресата — «Кому?» |
| `/new` | диалог нового окна (сбрасывает выбранного в `/sessions` адресата): машин на связи нет — «Нет машин на связи: запусти herald host»; несколько — «🪟 Новое окно. На какой машине?» с кнопками; затем каталог — кнопки последних корней сессий машины (`~` вместо `/home/<имя>`) и «или пришли путь от ~»; затем «Задача?». Кнопка перерисовывает сообщение следующим шагом, текст — следующий шаг новым сообщением. У каждого шага — «✖ Отмена» |
| задача в диалоге `/new` | запуск для демона машины, reply «⏳ Открываю окно на <машина>…»; итог демона — reply на то же сообщение: «🪟 Окно открыто на <машина>: …» или «⚠️ Окно не открылось на <машина>: …». Машина ушла со связи — запуск всё равно создан, демон заберёт его при опросе |
| `/cancel` | диалог `/new` отменён — «✖ Новое окно отменено.»; диалога нет — «Отменять нечего.» |
| другая `/команда` | «Неизвестная команда…» со списком (`/new`, `/sessions`, `/status`, `/cancel`, `/clear`, `/compact`, `/exit`); выбранный адресат сохраняется |
| `/sessions` | только сессии на связи (закрытые и молчащие не показываются), по блоку на сессию: имя жирным, машина и давность статуса, статус; кнопки выбора |
| кнопка сессии, затем текст | `directive` выбранной сессии (выбор — на одно сообщение) |
| `/status` (или reply `/status` на сообщение сессии) | статусы сессий на связи с давностью; reply — эта сессия с меткой 🟢/⚪; агент не участвует |
| входящее сессии не на связи | текст — reply «⚠️ … не на связи (…) — прочтёт, когда подключится»; кнопка — то же во всплывающем ответе |
| прочий текст | в живом диалоге `/new` — его шаг (reply на сообщение сессии — как обычно, не диалог); иначе подсказка «Кому?» |
| сессия закрылась (`bye`) с непрочитанными указаниями | сообщение «⚠️ … закрыта, указания не прочитаны:» со списком: новое окно их не получит |

- Любая команда, кроме `/new` и `/cancel`, и выбор сессии в `/sessions` прерывают диалог `/new`; команда выполняется как обычно. Ошибка шага (неизвестная машина, пустой текст) — «⚠️ …», диалог остаётся.
- Входящее из текста человека (указание, reply-ответ) подтверждается реакцией на его сообщении: ✍ — в ящике сессии, при `ack` агентом — 👀 (прочитано). Ответ кнопкой квитанции не получает: её роль играют всплывающий ответ и перерисованный вопрос.
- Сообщение пункта рисуется из состояния вопроса: у пачки — «Вопрос 2 из 3» под шапкой; решение агента («🤖 Принят A по таймауту»), ответ человека, переигрывания пункта. Кнопки: ответил человек (и переигрыванием) — убираются, переиграть можно reply; решил агент — варианты остаются для переигрывания; переведён в терминал — кнопок нет; «Жди меня» — только у открытого вопроса с таймаутом без удержания: нет кнопки — агент ждёт сам.
- Решение агента по пачке: на сообщениях отправленных пунктов — «🤖 …»; пункты, которых человек не видел, — одним итоговым сообщением «🤖 Агент решил по таймауту остальные вопросы: …» (reply — указание). Ответы в терминале на неотправленные пункты — итогом «👤 В терминале: …» на последнем отправленном.
- Пока вопрос открыт, в сообщении — сколько ждёт агент: «⏳ На раздумье 3 мин — до 14:32, потом агент решит сам.» (время — в поясе `HERALD_TIME_ZONE`; срок на другой день — с датой), «⏳ Время не ограничено: агент ждёт твоего ответа.» (без таймаута) или «⏸ Агент ждёт твоего ответа.» (после «Жди меня»). Срок не перерисовывается, когда истёк.
- `callback_data` ≤ 64 байт: `a:<вопрос>:<вариант>` (одиночный), `b:<вопрос>:<пункт>:<вариант>` (пачка), `h:<вопрос>`, `t:<вопрос>`, `s:<хеш ключа сессии>`, `n:<метка диалога>:h:<номер>` / `n:<метка>:d:<номер>` / `n:<метка>:x` (машина, каталог, отмена в `/new`). Длинный id варианта — ошибка `ask`.
- Доступ: апдейт от chat_id не из `HERALD_PEOPLE` игнорируется молча; вопрос или сессия другого человека — «⛔».
- Служебные правки (перерисовка вопроса, отметки) — best effort: сбой Telegram не отменяет сохранённое. Ошибка доставки `notify`/`ask` — ошибка сценария; вопрос при этом не сохраняется.

## Ожидание (`src/app/waiter.ts`)

Long poll без опроса базы: сценарии человека будят темы `q:<вопрос>`, `s:<сессия>` и `h:<человек>:<машина>` (новый запуск окна), ждущие перепроверяют хранилище до дедлайна.

- `awaitQuestion` — до ответа или таймаута (тогда вопрос `open`). «Жди меня» ожидание не завершает. Ответ, полученный ожиданием, сразу подтверждается — во входящих не повторяется.
- `awaitInbox` — непрочитанные сразу, иначе первые пришедшие; по таймауту — пусто.
- `HostService.poll` (`src/app/host.ts`) — невыданные запуски машины сразу (и выданы), иначе первые созданные; по таймауту — пусто. Машина отмечается в начале и в конце ожидания.

## HTTP API (`src/http`)

`POST /v1/<действие>`, тело и ответ — JSON, заголовок `Authorization: Bearer <токен>` (токен → человек). Сессия вызывающего — поле `session: { host, root, name?, instance? }` в каждом теле; каждое обращение агента отмечает её активной. Демон машины (`/v1/host/*`) шлёт то же поле: машина — `session.host`, сессия не регистрируется.

| Путь | Тело (кроме `session`) | Ответ |
|---|---|---|
| `/v1/notify` | `text` | `{ ok: true }` |
| `/v1/ask` | `text`, `options?: [{ id, text }]`, `recommended?` — или `questions: [{ text, options?, recommended? }]` (пачка); `timeoutMs?` | `{ question }` |
| `/v1/question` | `id`, `waitMs?` | `{ question }` — после ответа, перевода в терминал (`status: open`, `terminalAt`) или по истечении `waitMs` (`status: open`) |
| `/v1/decide` | `id`, `option` или `text` — или `answers: [{ item, option \| text }]` (пункты без ответа — рекомендованные), `reason` | `{ question }`; вопрос без таймаута, удержанный или переведённый — 400 |
| `/v1/answered` | `id`, `option` или `text` — или `answers` | `{ question }`: человек ответил в терминале, сообщение — «👤 Принят A (в терминале)», без кнопок |
| `/v1/to-terminal` | `id?` | `{ questions }` — вопрос или все открытые вопросы сессии переведены в терминал; во входящие не кладётся |
| `/v1/status` | `text` | `{ ok: true }` |
| `/v1/title` | `text` | `{ ok: true }` — название сессии |
| `/v1/bye` | — | `{ ok: true }` — окно закрыто, сессия ⚪ |
| `/v1/inbox` | `waitMs?`, `kinds?: string[]` | `{ items }` — непрочитанные (`kinds` — только этих видов); пусто — ждёт первых до `waitMs` |
| `/v1/ack` | `ids: string[]` | `{ read }` — id впервые прочитанных |
| `/v1/host/poll` | `waitMs?` | `{ launches }` — невыданные запуски машины `session.host` (выдаются один раз); пусто — ждёт первых до `waitMs`. Отмечает машину на связи |
| `/v1/host/done` | `id`, `ok: boolean`, `text` | `{ ok: true }` — итог запуска; человеку reply на его сообщение с задачей. Повтор — 400, запуск другого человека или машины — 403, нет запуска — 404. Итог сохраняется до отправки: сбой Telegram (502) не даст повторить |
| `GET /health` | — (без токена) | `{ ok: true }` |

- `question`: `{ id, text, options, recommended?, status, askedAt, deadlineAt?, heldAt?, terminalAt?, resolution?, lateAnswers, items }`; `items` — пункты `{ text, options, recommended?, resolution?, lateAnswers }`, плоские поля — первый пункт (у одиночного вопроса — сам вопрос); `item`: `{ id, kind, text, questionId?, option?, createdAt }`; `launch`: `{ id, dir, prompt, createdAt }` (типы — `src/http/wire.ts`, общие с клиентом).
- `waitMs` урезается до `HERALD_MAX_WAIT_SECONDS`: ждать дольше клиент должен переподключением.
- Ошибки — `{ error }`: 400 — неверный запрос или правило домена, 401 — токен, 403 — чужой вопрос, сессия или запуск, 404 — нет пути или объекта, 405 — не POST, 502 — сбой Telegram (`notify`/`ask` не доставлены), 500 — прочее (в лог).

## Сервер (`src/server`)

Запуск — `bun src/server/main.ts` из каталога с `.env` (Bun читает его сам). Ошибка конфига — код 1; SIGINT/SIGTERM — остановка опроса Telegram, обрыв long poll (клиенты переподключаются), закрытие базы, код 0.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HERALD_TOKENS`, `HERALD_PEOPLE` | — (обязательны) | доступ, см. «Доступ» |
| `HERALD_BOT_TOKEN` | — (обязательна) | токен бота из BotFather |
| `HERALD_PORT`, `HERALD_HOSTNAME` | `4518`, `127.0.0.1` | где слушать; наружу — через nginx |
| `HERALD_DB` | `./data/herald.db` | SQLite (WAL); каталог создаётся |
| `HERALD_MAX_WAIT_SECONDS` | `50` | потолок одного long poll (≤ 240; ниже `proxy_read_timeout` nginx — 60 с) |
| `HERALD_TIME_ZONE` | пояс системы | пояс IANA (`Asia/Oral`), в котором человеку показано время — срок вопроса |
| `HERALD_TELEGRAM_API` | `https://api.telegram.org` | адрес Bot API (в тестах — фейк) |
| `HERALD_RETENTION_DAYS` | `14` | срок хранения для `bun run purge` (целое ≥ 1), см. «Хранение»; сервер его не читает |

Telegram опрашивается long polling `getUpdates` (25 с); offset хранится в базе и переживает перезапуск. Сбой разбора апдейта пишется в лог, апдейт не повторяется. Bot API: сеть и 5xx — повтор с паузой, 429 — по `retry_after`, прочие 4xx — ошибка сразу.

## Хранение (`src/domain/retention.ts`, `src/server/purge.ts`)

В базе только оперативные данные, бэкапа нет. Срок хранения R (`Retention`, по умолчанию 14 дней). Граница — `now − R`. Очистку запускают снаружи раз в сутки: у нас — служба server-ops `herald-retention` ([deploy.md](deploy.md)).

| Что | Удаляется |
|---|---|
| Сессия | последнее обращение агента раньше границы. Вместе с ней — её вопросы (и открытые), входящие (и непрочитанные), связи с сообщениями, выбранный в `/sessions` адресат |
| Вопрос `answered` / `decided` | задан раньше границы |
| Вопрос `open` | только вместе с сессией: агент без таймаута может ждать сколько угодно |
| Прочитанное входящее | прочитано раньше границы; непрочитанное — только вместе с сессией |
| Связь с сообщением | связь вопроса или входящего — вместе с ними; связь уведомления — создана раньше границы (`created_at`, v5) |
| Машина | последнее обращение демона раньше границы (вернётся при следующем опросе) |
| Запуск окна | создан раньше границы — в любом состоянии |
| Диалог `/new` | начат раньше границы (живым он остаётся 1 ч) |
| `telegram_offset` | никогда |

Запуск — `bun run purge [--days N] [--dry-run]` из каталога с `.env` (база — `HERALD_DB`; файла нет — ошибка). Срок — `--days`, иначе `HERALD_RETENTION_DAYS`, иначе 14.
- Очистка идёт одной транзакцией (`BEGIN IMMEDIATE`) рядом с работающим сервером: WAL и `busy_timeout`.
- `--dry-run` считает то же и откатывает.
- Вывод — одна строка JSON `{ cutoff, days, dryRun, deleted, remaining, dbBytes }`: `deleted` и `remaining` (что останется) — счётчики `sessions`, `questions`, `inbox`, `links`, `targets`, `hosts`, `launches`, `dialogs`; `dbBytes` — страницы × размер страницы.
- Коды выхода: 0 — успех, 1 — ошибка (текст в stderr).
- `VACUUM` не делается: свободные страницы SQLite займёт заново.

Что видит человек: кнопка на удалённом вопросе — «⚠️ вопрос устарел и удалён»; reply на сообщение без связи — «Кому?».

## CLI (`src/cli`, клиент — `src/client`)

`herald` — тонкий слой над HTTP API для pi и любого агента с shell. Ставится `bun run link` → `~/.local/bin/herald`.

Настройки — `~/.config/herald/config.json` `{ serverUrl, token, host }`; `HERALD_URL`, `HERALD_TOKEN`, `HERALD_HOST` важнее файла, `HERALD_CONFIG` — другой путь. `host` по умолчанию — имя машины. Сессия: корень git текущего каталога (вне git — сам каталог) или явное имя `--session <имя>` / `HERALD_SESSION`. Внутри агента к корню добавляется окно, чтобы параллельные окна одного проекта не делили ящик. В Claude Code окно — процесс Claude Code: 4 символа хэша его pid и времени старта (канал берёт pid родителя, CLI — `CLAUDE_PID`, который Claude Code ставит своему Bash). Канал и CLI одного окна — одна сессия, `/clear` её не меняет (MCP-сервер живёт, меняется только id разговора); перезапуск или `--resume` — новое окно. Без `CLAUDE_PID` — первые 4 символа `CLAUDE_CODE_SESSION_ID`. В pi (`PI_SESSION_ID` — pi ставит его своему bash) окно — первые 4 символа id сессии; `/clear` — новая сессия, новое окно.

| Команда | Вывод (JSON в stdout) |
|---|---|
| `herald notify <текст>` | `{ ok: true }` |
| `herald status <текст>` | `{ ok: true }` — в Telegram не отправляется |
| `herald title <текст>` | `{ ok: true }` — название сессии в шапке |
| `herald ask <вопрос> [-o "A: текст"]… [--recommended A] [--timeout <с>]` | `{ id, status, by?, option?, text?, reason? }`; `--timeout` уходит на сервер сроком вопроса; без него ждёт бесконечно, `decide` по вопросу запрещён; человек нажал «Жди меня» до срока — после срока ждёт дальше, без срока |
| `herald ask --questions '<JSON>' [--timeout <с>]` | пачка `[{ "text", "options": [{ "id", "text" }], "recommended" }]`; `{ id, status, items: [{ item, by, option?, text?, reason? }] }` |
| `herald decide <id> (<вариант> \| --text <текст> \| --answers '<JSON>') --reason <причина>` | то же, `status: decided`; `--answers '[{ "item": 2, "text": "…" }]'`, прочие пункты — рекомендованные |
| `herald answered <id> (<вариант> \| --text <текст> \| --answers '<JSON>')` | то же, `status: answered` — человек ответил в терминале |
| `herald to-terminal [<id>]` | `[question…]` — вопрос или все открытые вопросы сессии переведены в терминал |
| `herald inbox [--wait <с>] [--ack]` | `[{ id, kind, text, questionId?, option?, createdAt }]`; `--ack` — сразу подтвердить выданное |
| `herald ack <id>…` | `{ read: [id…] }` |
| `herald self <команда> [--message <текст>] [--timeout <с>] [--delay <с>] [--foreground]` | `{ ok: true, pane, log }` — самосброс ушёл фоном; с `--foreground` — `{ ok: true }` или `{ ok: false, reason }` (код 1) |
| `herald hook` | ничего; хук Claude Code — см. «Самосброс» |
| `herald spawn <каталог> [--prompt <задача>] [--tmux <сессия>] [--timeout <с>]` | `{ ok: true, pane, window, dir }` — новое окно агента, см. «Окна агентов»; ошибка — stderr, код 1 |

- `ask`: `status` — `answered` (ответ человека), `decided` (решение агента), `timeout` (нет ответа), `terminal` (человек перевёл вопрос в терминал: спроси у себя, закрой `herald answered`); `text` у варианта — его текст.
- Коды выхода: `0` — готово, `2` — `ask` без ответа по таймауту, `3` — `ask` переведён в терминал, `1` — ошибка (аргументы, настройки, отказ сервера; текст — в stderr).
- Ожидание (`ask`, `inbox --wait`) — long poll кусками до своего таймаута: сбои сети и 5xx пережидаются, прочие ошибки — сразу.

### Самосброс (`src/terminal`)

Агент сам сбрасывает контекст и продолжает работу: `herald self /clear --message "<с чего продолжить>"` — последним действием хода. Сообщение — всё, что чистый агент будет знать: трек, фаза, задача, путь к плану.

**Когда:** на границах фаз трека — обязательно; чаще (например, между задачами фазы) — если это целесообразно: контекст разросся, следующая задача от прежнего не зависит, а всё нужное для неё записано в плане или сообщении.

- **Куда:** только своя панель tmux (`TMUX_PANE`); вне tmux — код 1 сразу. Команда — с `/`, в одну строку; сообщение может быть многострочным (набирается вставкой, `paste-buffer -p`).
- **Фоном:** CLI проверяет аргументы и запускает себя же отдельной сессией (`setsid -f`, переживает конец хода и Bash агента) с `--foreground`; вывод фонового процесса — `$XDG_STATE_HOME/herald/self/<панель>.log` (по умолчанию `~/.local/state/…`).
- **Когда набирать — по хукам** Claude Code, а не по таймеру. `herald hook` (хук `Stop` и `SessionStart`, настройка — `docs/install.md`) пишет метку `{ event, source, at }` панели в `…/herald/hooks/<панель>.<событие>.json`; stdout пуст, код всегда 0. Самосброс ждёт метку `Stop` позже своего запуска (ход закончен, поле ввода свободно) → набирает команду → для `/clear` и `/compact` ждёт `SessionStart` с `source` `clear` / `compact` позже набора → пауза 1 с → набирает сообщение. Прочие команды — сообщение через 1 с после набора.
- **Без хуков** (pi, другие агенты) — `--delay <с>`: команда сразу (агент занят — она в очереди), сообщение через N с; момент — на совести вызывающего.
- **Срок** каждого ожидания — `--timeout` (600 с). Сигнала нет или tmux не набрал — сообщение не набирается, человеку `notify`: причина, команда и текст сообщения (его можно ввести вручную).

### Окна агентов (`src/terminal/launcher.ts`)

Человек далеко и хочет параллельного агента для другой задачи — пишет указание активному агенту, тот вызывает `herald spawn <каталог> --prompt "<задача>"`. Лишнее окно закрывается указанием «закройся» — агент вызывает `herald self /exit` (окно tmux закрывается вместе с Claude Code, сессия гаснет). Обе подсказки — в инструкциях канала.

- **Каталог** — `~/…`, абсолютный или относительный (от текущего); после `realpath` — существующий каталог внутри домашнего, иначе ошибка.
- **Окно** — в tmux-сессии `agents` (`--tmux`): нет её — `new-session -d`, есть — `new-window -d`; имя окна — имя каталога. Смотреть — `tmux attach -t agents`.
- **Команда** — без shell: `claude --dangerously-load-development-channels server:herald -- <задача>` (флаг забирает значения после себя, поэтому задача — после `--`). `claude` — полный путь из `PATH` вызывающего: окно получает окружение сервера tmux.
- **Стартовые диалоги** проходятся по экрану (`capture-pane`, раз в 0,5 с), клавиша — по положению курсора: в «доверять папке» курсор на «No, exit» — Down, на «Yes, I trust this folder» — Enter; «I am using this for local development» — Enter. Окно на старте может потерять нажатие — та же клавиша на том же экране повторяется не чаще раза в секунду. Готово — баннер «Channels (experimental)». Не дождался за `--timeout` (60 с) или окно закрылось — ошибка с хвостом экрана. Тексты — Claude Code 2.1.326, при смене правятся константы `AgentLauncher`.
- Новая сессия появляется в `/sessions`, когда канал нового окна зарегистрируется.

## Канал (`src/channel`)

MCP-сервер по stdio для Claude Code — тонкий слой над тем же клиентом, что у CLI. Capability `experimental: { 'claude/channel': {} }` (и `'claude/channel/permission'` при `HERALD_PERMISSION_RELAY=1` в режиме событий). Подключение — `docs/install.md`.

**Режим** — по флагам родителя (Claude Code): `/proc/<ppid>/cmdline`, иначе `ps -o args=`. Изнутри MCP его не узнать: рукопожатие с флагом и без одинаковое, а события без флага Claude Code молча отбрасывает.
- **События** — есть `--dangerously-load-development-channels server:herald` (значения через пробел или запятую, `=`-форма). `--channels server:herald` не считается: несогласованный сервер Claude Code отбрасывает.
- **Без событий** — флага нет. Инструкции сервера говорят «Канал не подключён», появляется инструмент `inbox`, цикл входящих берёт только `command` (пульс и `/clear`, `/compact` остаются), указания и ответы ждут в ящике, пока агент их не заберёт. При старте человеку уведомление «⚠️ Окно запущено без канала…» (не у `claude -p`). Подтверждения действий нет.
- `HERALD_CHANNEL_EVENTS=1|0` задаёт режим явно; аргументы не прочитать — режим событий (как раньше).

| Инструмент | Аргументы | Результат |
|---|---|---|
| `reply`, `notify` | `text` | уведомление человеку |
| `ask` | `text`, `options?: [{ id, text }]`, `recommended?` — или `questions` (пачка до 10); `timeout_seconds?` | сразу id вопроса; ответ — событием (без событий — через `inbox`), у пачки — одним, когда отвечены все пункты. Без `timeout_seconds` `decide` запрещён |
| `decide` | `question_id`, `option` или `text` — или `answers: [{ item, option \| text }]`, `reason` | решение агента |
| `answered` | `question_id`, `option` или `text` — или `answers` | человек ответил в терминале: вопрос закрыт |
| `to_terminal` | `question_id?` | вопрос или все открытые вопросы сессии уходят из Telegram; текстом — что уже отвечено и что спросить. Инструкция канала: человек в терминале просит спросить здесь («тут») — вызвать его и задать пункты своим UI (AskUserQuestion) |
| `status` | `text` | статус сессии (в Telegram не отправляется) |
| `title` | `text` | название сессии в шапке; инструкция канала просит задать его в начале работы |
| `inbox` | `wait_seconds?` (до 600) | только без событий: непрочитанные `directive`, `answer`, `late-answer`, `to-terminal`, `hold` текстом (`kind=… item_id=… question_id=… option=…`, ниже — `content` как в событии), затем `ack`; пусто — ждёт до `wait_seconds` |

Входящие (режим событий): цикл long poll `inbox` → `notifications/claude/channel` `{ content, meta }` → `ack` (подтверждение прочтения — после доставки; сбой — повтор, событие может прийти дважды). Закрытие (Claude Code закрыл stdio, SIGTERM/SIGINT) — `bye` (best effort), затем выход; без него сессия станет ⚪ через 2 мин.

Команда (`command`) событием не идёт: канал набирает её в панели tmux окна (`TMUX_PANE`, наследуется от Claude Code; `src/terminal/tmux.ts`) — `Ctrl+U` (очистить черновик; вернуть — `Ctrl+Y`), команда, `Enter`. Агент занят — Claude Code ставит команду в очередь и выполняет после хода. Окно не в tmux или сбой tmux — человеку уведомление «⚠️ <команда> не выполнена: …». После `/clear` процесс канала тот же — сессия и её ключ не меняются; канал ставит ей статус «🧹 /clear — контекст сброшен, жду указаний» (после `/compact` — «🗜 /compact — контекст сжат»), чтобы в `/sessions` не висел статус прежнего разговора.

| `meta.kind` | `content` | прочие `meta` |
|---|---|---|
| `directive` | текст указания | `item_id` |
| `answer` | «Ответ на вопрос <id>: …» | `item_id`, `question_id`, `option?` |
| `late-answer` | «Переигрывание вопроса <id>: …» | `item_id`, `question_id`, `option?` |
| `to-terminal` | что уже отвечено и что спросить (текст входящего) | `item_id`, `question_id` |
| `hold` | «Человек нажал «Жди меня» на вопросе <id>: решать самому нельзя — жди его ответа без срока.» | `item_id`, `question_id` |

Подтверждение действий: `notifications/claude/channel/permission_request` `{ request_id, tool_name, description, input_preview }` → вопрос «🔐 Разрешить <tool>?» с вариантами `allow`/`deny` → ответ человека → `notifications/claude/channel/permission` `{ request_id, behavior }`. «Разрешить» — `allow`, «Запретить» и свободный текст — `deny`; поздний ответ отбрасывается; событием в сессию не идёт.

## Расширение pi (`src/pi`, пакет — `integrations/pi`)

Расширение на время сессии pi (`session_start` … `session_shutdown`) — то же, что канал для Claude Code: пульс, указания и команды из Telegram. Работает в Node (pi — Node-приложение) и в Bun: только API Node. Подключение — `docs/install.md`. Сессия — та же, что у `herald` в bash этой сессии pi (корень git + окно из id сессии).

- Входящие: цикл long poll `inbox` с `kinds: directive, late-answer, command, to-terminal` → агенту → `ack`. Ответы (`answer`) расширение не берёт: их ждёт сам `herald ask`, иначе агент получил бы ответ дважды; без ожидания — `herald inbox`. `to-terminal` берёт: если агент ждал вопрос в `herald ask` (код 3), сервер уже отметил его прочитанным. `hold` не берёт: агент pi ждёт вопрос в `herald ask`, а тот после «Жди меня» ждёт без срока.
- Указание и поздний ответ — сообщение пользователя (`sendUserMessage`, `deliverAs: steer`: агент занят — после текущих инструментов): «Указание человека из Telegram (herald): …» с напоминанием отвечать через `herald notify`; «Переигрывание вопроса <id> (herald): …»; перевод в терминал — что спросить и как закрыть (`herald answered <id> --answers …`). Во время сжатия контекста pi сообщения отклоняет — доставка ждёт его конца.
- Команда — команда расширения: `/clear` → `/herald-clear` (дождаться конца хода, новая сессия pi), `/compact` → `/herald-compact` (дождаться конца хода, сжатие). Сбой — человеку «⚠️ <команда> не выполнена: …».
- `session_shutdown` — `bye` (кроме `reload`). Новая сессия (`/new`, `/clear`, `/resume`, `/fork`) — новое окно со своим ящиком.
- `pi -p` (режимы `print`, `json`, например выжимка chronicle) — расширение молчит. Нет настроек herald — предупреждение в pi, сессия работает без herald.
