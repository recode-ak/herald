# Модель herald

Сущности, состояния и правила домена (`src/domain`). Домен синхронный, без ввода-вывода; время — мс эпохи, передаётся снаружи. Нарушение правила — `DomainError`, ошибка конфига доступа — `AccessConfigError`.

Сценарии (`src/app`) — ниже, в разделах «Бот» и «Ожидание». HTTP API, команды CLI и инструменты канала — появятся в фазах 3–5 трека v1.

## Доступ (`access.ts`)

Кто пользуется herald. Строится из двух строк окружения сервера:

| Переменная | Формат | Смысл |
|---|---|---|
| `HERALD_TOKENS` | `человек:токен,…` | токен агента (по одному на машину/контур) → человек |
| `HERALD_PEOPLE` | `человек:chat_id,…` | человек → его chat_id в Telegram |

Правила: обе строки не пусты; токен и chat_id уникальны; у каждого человека с токеном есть chat_id; chat_id — целое (у групп отрицательный). Из Telegram принимаются апдейты только от chat_id из `HERALD_PEOPLE`.

## Сессия (`session.ts`)

Где работает агент. Регистрируется при первом обращении, принадлежит человеку токена.

| Поле | Смысл |
|---|---|
| `key` | `host:корень` (корень git без хвостового `/`) или `host:@имя` при явном `--session` |
| `project` | имя корня (`u7-school`) или имя сессии |
| `lastSeenAt` | последнее обращение агента; сессия активна, пока `now − lastSeenAt ≤ окно` |
| `status` | `{ text, at }` — последний статус от агента, ≤ 500 символов; в Telegram сам не отправляется |

## Вопрос (`question.ts`)

Вопрос агента человеку: текст, варианты `{ id, text }` (могут отсутствовать — тогда только свободный ответ), рекомендованный — из вариантов.

```
            answer (человек)
   open ──────────────────────▶ answered
     │  decide (агент, с причиной)
     └────────────────────────▶ decided
```

- `answer` — вариант или свободный текст. Если вопрос не `open`, ответ **поздний**: сохраняется в `lateAnswers`, первое решение не меняется (агент сам решает, переигрывать ли).
- `decide` — только из `open` и только без удержания; причина обязательна («по таймауту»).
- `hold` — кнопка «Жди меня»: вопрос остаётся `open`, агенту решать нельзя, человек ответит сам.
- `resolution` — `{ by: human | agent, option | text, reason?, at }`.

## Входящие (`inbox.ts`)

Что агент забирает из сессии.

| Вид | Когда | Поля |
|---|---|---|
| `answer` | ответ человека на открытый вопрос | `questionId`, `option` или текст |
| `late-answer` | ответ на уже решённый вопрос | `questionId`, `option` или текст |
| `directive` | указание человека сессии (reply или выбор в `/sessions`) | текст |

- Выдача — непрочитанные по времени создания, затем по id.
- Подтверждение прочтения (`ack`) атомарно: неизвестный id — ошибка, ничего не отмечено. Возвращает впервые прочитанные — по ним человеку уходит отметка «прочитано агентом».
- Ящик (`Inbox`) — одна сессия; элемент чужой сессии в него не попадает.

## Бот (`src/app/human.ts`, `agent.ts`)

Сообщения без разметки (`parse_mode` не используется). Шапка — `[host · проект]`.

| Действие человека | Результат |
|---|---|
| кнопка варианта на вопросе | `answer` (или `late-answer`, если вопрос уже решён), сообщение вопроса перерисовано |
| «Жди меня» | `hold`: агенту решать нельзя, в сообщении «⏸ Агент ждёт твоего ответа» |
| reply на вопрос | свободный ответ — так же, как кнопка |
| reply на другое сообщение сессии (уведомление, отметку) | `directive` этой сессии |
| `/sessions` | активные сессии (окно активности — настройка сервера): давность, статус, кнопки выбора |
| кнопка сессии, затем текст | `directive` выбранной сессии (выбор — на одно сообщение) |
| `/status` (или reply `/status` на сообщение сессии) | последние статусы с давностью; агент не участвует |
| прочий текст | подсказка «Кому?» |

- Входящее подтверждается отметкой — reply «📥 в ящике сессии X»; при `ack` агентом она меняется на «✅ прочитано агентом».
- Сообщение вопроса рисуется из его состояния: решение агента («🤖 Принят A по таймауту»), ответ человека, переигрывания. Кнопки остаются всегда — для переигрывания.
- `callback_data` ≤ 64 байт: `a:<вопрос>:<вариант>`, `h:<вопрос>`, `s:<хеш ключа сессии>`. Длинный id варианта — ошибка `ask`.
- Доступ: апдейт от chat_id не из `HERALD_PEOPLE` игнорируется молча; вопрос или сессия другого человека — «⛔».
- Служебные правки (перерисовка вопроса, отметки) — best effort: сбой Telegram не отменяет сохранённое. Ошибка доставки `notify`/`ask` — ошибка сценария; вопрос при этом не сохраняется.

## Ожидание (`src/app/waiter.ts`)

Long poll без опроса базы: сценарии человека будят темы `q:<вопрос>` и `s:<сессия>`, ждущие перепроверяют хранилище до дедлайна.

- `awaitQuestion` — до ответа или таймаута (тогда вопрос `open`). «Жди меня» ожидание не завершает. Ответ, полученный ожиданием, сразу подтверждается — во входящих не повторяется.
- `awaitInbox` — непрочитанные сразу, иначе первые пришедшие; по таймауту — пусто.
